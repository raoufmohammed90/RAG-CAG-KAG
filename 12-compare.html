12 Comparison and decision guide Agenda

Choosing a pattern

Side by side, a decision guide, and how they combine.

    One question behind all three: how does the knowledge get into the window?

    Start simple. Add the next pattern only when the last one stops working.

    The same chat app, the same model and the same window. Only the way knowledge arrives changes.
    CAGLoad everything once, keep it cached, ask many times.
    RAGSearch the documents and bring only what each question needs.
    KAGStore the connections, then follow them or summarise them.

    A decision guide

    Ask these in order. Stop at the first yes.

    Start simple, climb only when needed

    Each step up handles more, and costs more to build and run. Measure before you climb.

    CAGKnowledge in the prompt, cached.
    RAGAn index and a search step.
    Better RAGHybrid search, reranking, metadata filters, multi-step search.
    GraphKAG or GraphRAG, where the questions need it.
    less to buildmore to build and run

    They combine

    Real systems rarely use just one pattern.

    CAG+RAG
    Cache the core knowledge everyone needs, and retrieve the long tail. The CAG paper's authors suggest exactly this hybrid.
    Caching+ any pattern
    Put the system prompt, tools and stable instructions first and cache them, whatever comes after.
    RAG+Graph
    KAG already mixes graph lookups with text retrieval. Or send only relationship questions to a graph.
    Router
    Classify each question first, then send it to the cheapest pattern that can answer it.
