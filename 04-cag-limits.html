Where CAG stops working

Five limits, and the step to retrieval.

    Real windows are bigger. So is real knowledge.

    The largest models today read around a million tokens. A company's knowledge is usually measured in many millions, and it keeps growing.

    ~600,000tokens in 1,000 pages of documents
    (about 450 words a page)
    ~1,000,000tokens in the largest context windows
    Many millionstokens in a wiki, ticket history,
    contracts and product docs
    Estimates use the rule of thumb from page 01: 1,000 tokens is about 750 English words. Other languages, code and tables use more tokens per word.

    Lost in a long window

    Fitting is not the same as being used well. Models find information at the start and end of a long input more reliably than in the middle.

    Illustrative shape of the finding in "Lost in the Middle" (Liu et al., TACL 2024): accuracy is highest when the relevant document is at the beginning or end of the input, and drops when it sits in the middle. Later studies report accuracy falling as inputs grow, even on simple tasks: in NoLiMa (ICML 2025), 11 of 13 long-context models scored below half their short-input level at 32,000 tokens.

    Every question pays for all of it

    Everyone sees everything

    With CAG, the same knowledge goes into every request, whoever is asking. A document in the window can end up in any answer.

    Hiding a document from some users means a separate knowledge set and cache per audience, which multiplies the cost. Telling the model "don't reveal this" is not access control.

    When CAG fits, and when to move on

    If any answer on the right is yes, load less: fetch only the passages each question needs. That is retrieval-augmented generation.
